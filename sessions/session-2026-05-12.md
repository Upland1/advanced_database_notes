## What I understood
- **The Power of ORM:** Using an Object-Relational Mapper allows developers to interact with the database using native, object-oriented programming concepts rather than raw SQL strings. This approach provides built-in security against SQL injection and makes the application entirely database-agnostic.
- **Simplifying Joins:** ORM relationships effectively map foreign keys to object attributes, completely bypassing the need to write complex, manual SQL `JOIN` statements. 
- **Database Version Control:** Migrations serve as a trackable, repeatable history of your database schema. They allow you to confidently move the database state forward (upgrading) or backward (downgrading) across different environments safely.
- **Downgrade Consequences:** When a database schema is downgraded to remove a specific column, that column and all the data it housed are permanently deleted, though the rest of the table's data remains untouched.
- **Transaction Lifecycles:** There is a distinct difference between staging a database transaction (adding it to a tracked session) and finalizing it (committing the actual SQL operations to the database). 
- **Troubleshooting State:** When automated migration tools fail midway through an execution (such as attempting to drop an index that no longer exists), the tool's tracking state falls out of sync with the actual database. Resolving this requires manually clearing the tool's memory and resetting the physical database tracking tables to start fresh.
