## What I understood
- **Automatic Transactions**: In Oracle, a transaction begins implicitly with the first DML statement (`INSERT`, `UPDATE`, `DELETE`); there is no need for a `BEGIN TRANSACTION` command.
- **Atomicity and Scope**: A `COMMIT` inside a procedure acts globally on the session. It saves all pending changes made by the caller, which can break the atomicity of a larger parent transaction.
- **Savepoints as Checkpoints**: `SAVEPOINT` allows for partial rollbacks, enabling a "retry" or "correction" logic without discarding the entire transaction's progress.
- **Single vs. Double Quotes**: Oracle strictly uses single quotes (`'`) for string literals and double quotes (`"`) for identifiers like column or table names.
- **Side Effect Isolation**: Operations involving external systems (email, SMS) should remain outside database transactions to avoid "hanging" the DB or sending messages for rolled-back actions.
