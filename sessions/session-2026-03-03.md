# Session – 2026 - 03 - 03

## Topics covered
Unlike aggregates that return one row per group, window functions keep every row while adding computed metrics such as running averages, rankings, counts, and totals.

- Analytic (window) functions
- OVER()
- PARTITION BY
- ORDER BY in windows
- Running aggregates
- Window frames (ROWS, RANGE)
- COUNT, AVG, SUM, MIN, MEDIAN as windows
- Ranking functions
- DENSE_RANK
- CTEs (WITH clause)
- Multi-table JOIN + ranking

---

## What I understood

### Window functions concept
- Perform calculations across related rows
- Do NOT collapse rows like GROUP BY
- Each row keeps its original data plus computed metrics

General structure:

```sql
AGG_FUNC(column) OVER (
  PARTITION BY column
  ORDER BY column
)
```

---

### Partitioning (group-like behavior without collapsing)

Calculate metrics per group while keeping all rows:

```sql
COUNT(*) OVER (
  PARTITION BY shape
)
```

Example learned:
- Count bricks per shape
- Median weight per shape

---

### Running aggregates
Use `ORDER BY` inside `OVER()` to compute progressive values:

```sql
AVG(weight) OVER (
  ORDER BY brick_id
)
```

Example:
- Running average weight by brick_id

---

### Window frames (ROWS / RANGE)

Control which rows are included in the calculation window.

#### ROWS
Physical row positions:

```sql
ROWS BETWEEN 2 PRECEDING AND 1 PRECEDING
```

Example:
- Minimum colour of the two previous rows

#### RANGE
Value-based range:

```sql
RANGE BETWEEN CURRENT ROW AND 1 FOLLOWING
```

Example:
- Count rows with same weight and next value

---

### Multiple window calculations in one query

You can compute several analytics at once:

```sql
SUM(weight) OVER (PARTITION BY shape)
SUM(weight) OVER (ORDER BY brick_id)
```

Then filter results using a CTE:

```sql
WITH totals AS (...)
SELECT *
FROM totals
WHERE weight_per_shape > 4
  AND running_weight_by_id > 4;
```
