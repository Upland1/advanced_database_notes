# Session – 2026 - 02 - 17

## Topics covered
This session introduced multi-table queries and how relational databases organize data using normalization.  
Instead of storing everything in one large table, data is split into multiple related tables to reduce duplication and improve structure.

To retrieve related information across tables, we use JOIN operations (`INNER JOIN`, `LEFT JOIN`, `RIGHT JOIN`, `FULL JOIN`) combined with primary keys and foreign keys.

- Primary key → Column that uniquely identifies each row
- Foreign key → Column that references a row in another table
- Database normalization
- Splitting data into multiple related tables
- Multi-table queries using JOINs
- INNER JOIN
- LEFT JOIN
- RIGHT JOIN
- FULL JOIN
- Handling NULL values in joins

## What I understood

### Database normalization
- Reduces duplicated data
- Makes the database more organized
- Tables grow independently
- Improves consistency and maintenance
- Trade-off: queries become more complex

### Keys
- **Primary key (PK)** uniquely identifies a row
- **Foreign key (FK)** connects one table to another
- Keys allow tables to be related

### INNER JOIN
- Returns only rows that match in both tables
- Excludes unmatched rows

```sql
SELECT *
FROM movies
INNER JOIN boxoffice
ON movies.id = boxoffice.movie_id;
```

### LEFT JOIN
- Keeps all rows from the left table
- Adds matching rows from the right table
- Non-matching values become NULL

```sql
SELECT *
FROM movies
LEFT JOIN boxoffice
ON movies.id = boxoffice.movie_id;
```

### RIGHT JOIN
- Keeps all rows from the right table
- Adds matching rows from the left table
- Non-matching values become NULL

### FULL JOIN
- Keeps all rows from both tables
- Missing matches are filled with NULLs

### JOIN syntax structure
- Combine tables first
- Then apply filtering, sorting, and limits

```sql
SELECT columns
FROM tableA
JOIN tableB
ON tableA.id = tableB.id
WHERE conditions
ORDER BY column
LIMIT number OFFSET number;
```
